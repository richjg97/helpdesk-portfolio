Windows 10 DNS Troubleshooting

DNS helps your computer find websites by their names. For this project, I intentionally changed the DNS setting in a Windows 10 virtual machine to see what would happen. I then tested the connection, figured out what was causing the lookup failure, and fixed it.

How I Investigated and Fixed It

Here are the steps I took. I included screenshots from the actual lab so you can see the results.

01

Check the working configuration

I first ran ipconfig /all to check the network settings. The DNS server was 10.0.2.3. I also ran nslookup example.com and ping 1.1.1.1. Both worked, and the ping had no packet loss.

Why I did this: I wanted to make sure everything was working before changing anything.

02

Change just the DNS server

Next, I changed only the preferred DNS server to 192.0.2.53, a reserved address used for documentation and testing. I left the IP address set to automatic and used ipconfig /all to confirm the new DNS setting.

Why I did this: Changing just one setting made it easier to see what caused the problem.

03

Reproduce the failed lookup

I tried nslookup example.com again. This time it repeatedly showed DNS request timed out instead of returning the address.

What I found: The DNS server I entered was not answering the request. The timeout mattered here; the words “Server: Unknown” alone would not prove a failure.

04

Test a destination by IP address

I ran ping 1.1.1.1 to test a connection using an IP address instead of a website name. All four pings came back, with 0% packet loss and an average time of about 8 ms.

What I found: I could still reach that IP address, even though the DNS lookup was failing. That does not mean every website or internet service was working.

05

Restore automatic DNS

I went back to the Ethernet adapter settings and selected “Obtain DNS server address automatically.” After that, ipconfig /all showed the original DNS server, 10.0.2.3, again.

Why this worked: The problem was the DNS server setting itself. Clearing the DNS cache would not have corrected that address.

06

Verify the repair

To make sure the fix worked, I ran nslookup example.com one more time. It returned both IPv4 and IPv6 addresses, which showed that DNS resolution was working again.

Final result: The DNS lookup worked after I restored the setting. I did not run another ping or test websites in a browser after the fix.

What I Learned

Check one thing at a time. I learned that a ping to an IP address can work even when a DNS lookup fails. Running both tests helped me narrow down the issue.

Fix the setting that caused the problem. Since I had changed the DNS server, the right fix was to restore it. Flushing the DNS cache would not have changed the server address.

Always test the fix. I did not stop after changing the setting. I ran nslookup again to confirm that it could find the website’s addresses.

Keep clear notes. Saving screenshots of the original settings, the failure, and the successful lookup helped me show what I did and how I checked the result.
